Platform: clicking a link shows the same progress bar as pressing a button

Pressing Save has driven the bar at the top of the page since the action system
was built. Clicking a link drove nothing — and a link is the more common thing
to press. The current page stays fully rendered and interactive while the next
one is fetched, so a slow section looks exactly like a click that missed, and
the reasonable response to a click that missed is to click again.

One listener at the document rather than per-link. The App Router has no
router-events hook; useLinkStatus is the documented tool and reports on one
Link from inside that link's own subtree, so using it would mean editing every
link in the product and remembering to do so for every link anybody adds.
Listening once covers every link that exists and every link that will exist,
including plain anchors.

The bar stops when the pathname OR the query string changes. The query string
matters as much as the path — a case page moves between sections with
?section=, so watching the path alone would leave the bar running forever on
the screens people use most. A ten-second timeout covers clicks that
legitimately go nowhere, because a bar that never stops is worse than no bar.

The cursor goes to `progress` at the same time. The bar is a thin line at the
top of a tall page; the cursor is where the person is already looking.

Also in this ship: the profile section tabs wrap onto a second row instead of
scrolling, and the threshold for hiding sections behind "More" goes from twelve
to twenty-four.
