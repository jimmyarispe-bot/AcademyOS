Admissions: one form for four campuses, and a lead list you can click to

Three changes that were written to disk but never staged, so the ship script
found nothing to commit. They go out together.

1. NAVIGATION. ADMISSIONS_TABS and SUB_NAV rendered only inside
   AdmissionsLegacyView. The default admissions page — the one the sidebar
   opens — showed the work queue and nothing else, so the Lead List, Pipeline
   Board, Executive view, Reporting, State Funding, Funding Programs,
   Reconciliation, Automation, Workflows, Templates and Checklist Settings were
   reachable only by typing ?view= or a sub-route by hand. Both rows move into
   one AdmissionsNavigation component rendered on both screens, so a
   destination added to either array appears everywhere.

2. INTEREST FORM v3 — the shared trunk. The four campus applications ask three
   things inconsistently and no campus asks all three: FL, GA and Virtual ask
   for a birthdate while HS asks for an AGE from a dropdown; all four ask for a
   mailing address while JAG asked for none; only GA asks how a family heard
   about the school. All three are now asked of everyone, once.

   AGE IS DERIVED, NEVER STORED. Age is not a fact about a person, it is a fact
   about a person and today. Stored, it is wrong within a year and the row
   cannot tell you whether it was ever right. ageFromDateOfBirth() is the one
   place it is computed, with tests — including the one that matters: a
   date-only string parsed as UTC lands on the previous day west of Greenwich
   and ticks the age over early for every family in the United States.

3. INTEREST FORM v4 — the campus sections. visibleWhen has existed on sections
   and questions since the engine was built and no published version ever set
   it. Five sections now appear the moment a family picks their campus. School
   ids are resolved by name inside the migration rather than pasted, because a
   condition that matches nothing renders no section and logs no error.

   Returning students are deliberately absent. GA's paper form branches on new
   versus returning because paper cannot know who you are; JAG can. Returning
   families sign in, and re-enrolment is its own flow.

   HS differs from its paper form by instruction: student email only, no mobile
   number, and the 60-second video asked as written narrative instead.

FOUR THINGS CAUGHT BY READING RATHER THAN ASSUMING, ANY OF WHICH WOULD HAVE
SHIPPED LOOKING FINE:

  * InterestFormRenderer only drew a multiselect when optionSource was
    "funding_sources". A multiselect with plain options fell through to the
    generic text input — a one-line box for a ten-option question.
  * Those checkboxes need name attributes; the form submits new FormData(form),
    which cannot see an unnamed input.
  * The submit validator skips hidden questions before the required check, so
    choosing GA is not rejected for leaving Florida's fields empty. Had it not,
    the feature would have been dead on arrival.
  * Nothing in JAG charges a card. The Square code is read-side only, so the
    $100 application fee on all four forms still cannot be taken.

No file uploads: the engine has no file field. Documents stay in the portal's
DocumentCenter, where an inquiry does not block on a parent finding a PDF.
