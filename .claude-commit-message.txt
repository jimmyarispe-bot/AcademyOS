Platform: every email address and phone number is clickable

Two places in the whole product made contact details tappable — the People
Directory and the admissions waiting list. Everywhere else they were plain
text, which on a phone means reading a number off the screen and typing it into
the dialler. Staff read these on a phone as often as at a desk.

EmailLink and PhoneLink, used across the admissions case, the lead list, the
executive dashboard, the student profile's guardians and emergency contacts,
families, HR, the staff directory, the parent invite list and the admin user
tables.

Neither reformats what is shown. The number a family gave is how that family
recognises their own number, so the display stays exactly as stored and only
the dial target is normalised — ten digits get +1, an international number
keeps its own prefix, an extension is dropped rather than gambled on because
some diallers silently fail on `;ext=`. A value that is not an address or a
number renders as plain text rather than disappearing: "ask mum" is still the
only contact detail on file.

Also fixes ProfileItem title-casing anything it was given, which is why the
questionnaire panel read "Jimmy.Arispe@Gmail.Com" — CSS capitalising an address
that is not capitalised anywhere else and that a reader might retype. It now
applies only to plain strings, which is what it was written for.
